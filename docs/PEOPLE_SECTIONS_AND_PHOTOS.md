# Свои разделы и фото людей

1 ноября 2026. Вход: **План → Люди → новая или существующая карточка**.

## Поведение

- Три привычных списка остаются: интересы, увлечения, идеи для подарков.
- «Добавить свой раздел» создаёт список со своим названием. Например, «Любимые
  места», «Размеры одежды», «Что обсудить». Пункты добавляются отдельно; вставка
  нескольких строк создаёт несколько пунктов. Раздел можно переименовать или убрать.
- Разделы сворачиваются; раскрыт один, чтобы длинная карточка не перегружала экран.
- «Добавить фото» открывает системную медиатеку. Можно заменить/убрать фото.
  Отмена выбора сохраняет прежнее. Фото показано в списке и календаре дней рождения.
- Изменения применяются по «Сохранить». Закрытие редактора отменяет черновик.
- Фото хранится внутри локальной SQLite-карточки как небольшая миниатюра JPEG;
  нет зависимости от временного файла или сохранённого доступа к медиатеке.
  Оригинал и его метаданные не сохраняются. Фото исключено из контекста ИИ.

Schema 9, миграция `8.sqm` добавляет поля с безопасными дефолтами. Старые люди,
дни рождения и три списка заметок остаются на месте. API репозитория прежний.
Точные поля, лимиты, пути и платформенный bridge — в [CONTRACTS.md](CONTRACTS.md).

## Не проверено вручную

Физический iPhone, Android photo picker на устройстве, iCloud-загрузка,
разные EXIF-ориентации/очень большие исходники, VoiceOver и Release performance
этого изменения. Чтение/обработка ограничены миниатюрой; Android fallback API 24–27
компилируется, но отдельно на старом устройстве не запускался. Полноценного
редактора кадрирования нет: используется центральный квадрат.

Платформенные решения опираются на существующий
[Android photo picker](https://developer.android.com/training/data-storage/shared/photo-picker)
и [Apple PHPickerViewController](https://developer.apple.com/documentation/photosui/phpickerviewcontroller).
Доступ ко всей библиотеке фотографий не запрашивается.
